## Capabilities and admin workflows

| Server | Tools and intended workflow |
| --- | --- |
| Diagnostics | Existing `lookup_dns`, `check_email_dns`, `check_https`; new `deployment_readiness` combines DNS, mail DNS, root HTTPS, redirects and selected headers into one rollout report. New `trace_email` reconstructs supplied Received hops, explicit-date delays, Authentication-Results claims and SMTP/DSN outcomes for queue/delivery investigations. |
| Logs and configuration | Existing `parse_logs`, `summarize_logs`; new `extract_ci_failures` locates compiler/test/dependency/permission evidence with source lines; `analyze_http_trace` explains supplied status/redirect/retry/timing metadata offline; `validate_config` returns violations against a supplied bounded JSON schema. |
| Network | `inspect_subnet`, `plan_subnets`, `check_cidr_overlap` retain IPv4/IPv6 exact calculations, largest-first allocations, labels and explicit exhaustion; overlap evidence now has a return budget and exact total. |

No new endpoint is needed: deployment/mail diagnostics, supplied operational evidence and network planning are coherent workflows. No mailbox access, mail sending, arbitrary fetching, remote schema loading, paid data APIs or hosted inference was added.

Every successful response returns `structuredContent` plus an `admin` object (`summary`, `findings`, `nextSteps`, `limitations`) and readable text capped at 1,500 characters. Existing programmatic fields remain. Configuration error paths do not echo values. Capture URLs omit userinfo/query strings and sensitive headers. CI excerpts redact common credential assignments, with an explicit warning that this is not a complete secret scanner.

Email headers remain unverified supplied evidence. Caller-designated authserv IDs do not prove trust. Two/four/five-class SMTP outcomes distinguish reported acceptance, temporary failure and permanent rejection at the reported hop. Acceptance is not inbox delivery. Headers after the first blank line are ignored. Missing timezone or a full year prevents chronological inference. A regression fix ensures a `+0000` timezone cannot be mistaken for a missing four-digit year. This interpretation follows [SMTP](https://www.rfc-editor.org/rfc/rfc5321.html), [message format](https://www.rfc-editor.org/rfc/rfc5322.html) and [Authentication-Results trust guidance](https://www.rfc-editor.org/rfc/rfc8601.html).

JSON validation deliberately advertises a bounded subset: type/properties/required/additionalProperties/items/enum, numeric limits, string lengths and array lengths. It rejects unsupported keywords rather than silently passing refs, regex, formats or combinators. Schema work is capped at depth 20/1,000 nodes and 100 enum values; returned errors cap at 50 with exact totals.

The final eight failures remain visible: two repeated-email inputs shortened by the model; three altered log inputs; one wrong returned-record fact; one rate-limited extra attempt; and one changed allocation request. These are input-preservation/answer/agent-behavior limits, not eight failing deterministic tools. Use programmatic submission for long or repetitive input rather than having a small model retype it. These tests are automated admin-readability proxies, not an admin user study or proof of external demand. Single before/after passes do not establish statistical reliability improvement.

## Reusable research and enhancement loop

Invoke `$oldweb-mcp-lab` for research-only, propose, implement-and-evaluate or review work. It retains dated sources, capability comparisons, demand hypotheses, rankings, budget checks, decisions and test evidence across iterations. Catalogue presence, visits/downloads and stars stay distinct from successful calls. It prefers enhancing an existing workflow over creating another connection when appropriate. Default is one iteration; an unbounded request to loop caps at three iterations. The skill does not create its own schedule or authorize deployment/continued operation.

Example: `Use $oldweb-mcp-lab to run one research-and-proposal iteration using current catalogue capabilities, external OldWeb usage and the $25 monthly target. Save ranked ideas and the evidence; keep implementation for the selected scope.`

Recommendations: retain the bounded tools for the pilot, use exact programmatic payload submission for bulk evidence, and evaluate demand after actual directory exposure. Treat current adoption as inconclusive; successful internal tests do not justify expanding paid infrastructure. Consider trusted-header interpretation, richer SMTP code explanations and wider schema support only after observed admin demand and bounded-work tests.
